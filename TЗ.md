# Технічне завдання — «Точка мандрів» (Travel Budget Planner)

## 1. Вступ
«Точка мандрів» — це веб-додаток, який допомагає мандрівникам планувати бюджет подорожей.  
Сервіс дозволяє створювати маршрут, додавати витрати (транспорт, житло, харчування), вести облік і отримувати підсумкову вартість поїздки.

## 2. Мета і задачі
- **Мета:** створити простий веб-інструмент для планування бюджету подорожей з можливістю аналізу витрат.
- **Основні задачі:**
  - Додати створення подорожі з назвою, датами та країною.
  - Реалізувати можливість додавання витрат за категоріями.
  - Відображати статистику витрат у вигляді списку та діаграми.
  - Надати можливість зберігати і переглядати попередні подорожі.

## 3. Цільова аудиторія
- Індивідуальні мандрівники, студенти, фрілансери, які планують поїздки самостійно.
- Ключові сценарії:
  - Створення подорожі → додавання витрат → перегляд статистики.
  - Порівняння витрат різних подорожей.

## 4. Функціональні вимоги
1. **Створення подорожі**  
   Користувач вводить назву, дати, країну.  
   *Критерій приймання:* нова подорож з’являється у списку.
2. **Додавання витрат**  
   Користувач додає витрату (сума, категорія, опис).  
   *Критерій приймання:* витрата відображається у списку і враховується в сумі.
3. **Перегляд статистики**  
   Витрати відображаються у вигляді категорій + діаграми (Pie chart).  
   *Критерій приймання:* сума витрат коректна, діаграма оновлюється при зміні даних.
4. **Збереження даних**  
   Дані зберігаються у локальній БД (наприклад SQLite) або localStorage.  
   *Критерій приймання:* після перезавантаження дані залишаються.

## 5. Нефункціональні вимоги
- **Продуктивність:** сторінка завантажується < 1 сек, операції з витратами — миттєві.
- **Безпека:** використовується базова автентифікація (опційно).
- **Сумісність:** робота у Chrome, Firefox, Edge (останній реліз).
- **Логування:** помилки зберігаються у консоль/файл для відладки.

## 6. Обмеження та припущення
- Використання простого стеку: React + Node.js (Express) або лише фронтенд на React.
- Дані можуть зберігатись локально (без серверної частини) для демонстрації.
- Проєкт розрахований на 2–3 тижні розробки.

## 7. Інтерфейс користувача
- Головна сторінка — список подорожей + кнопка "Створити".
- Сторінка подорожі — форма додавання витрат + список витрат.
- Сторінка статистики — діаграма витрат за категоріями.

## 8. Архітектурні рішення
- **Фронтенд:** React + Tailwind CSS.
- **Бекенд (опційно):** Node.js + Express.
- **БД:** SQLite (або localStorage).
- **CI/CD:** GitHub Actions для автоперевірки комітів.
- **Деплой:** GitHub Pages або Vercel.

## 9. План робіт та етапи
- **Ітерація 1:** каркас проєкту, головна сторінка, створення подорожей.
- **Ітерація 2:** додавання витрат і статистики.
- **Ітерація 3:** збереження даних, базові тести, деплой на GitHub Pages.
- **Реліз 1.0.0:** готовий до демонстрації додаток.

## 10. Критерії приймання
- Можна створити подорож, додати витрати, переглянути статистику.
- Немає критичних багів.
- Дані не губляться при перезавантаженні сторінки.
- Код у репозиторії має теги, README, CHANGELOG.
