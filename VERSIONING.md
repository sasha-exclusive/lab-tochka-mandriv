# Політика версіонування для «Точка мандрів»

## Схема версій (SemVer)

Ми використовуємо **семантичне версіонування** (Semantic Versioning):  
`MAJOR.MINOR.PATCH`

- **MAJOR** – збільшується при зламі сумісності або великих змінах (наприклад, 1.x.x → 2.0.0).
- **MINOR** – нові фічі, які сумісні з попередніми версіями (наприклад, 1.0.0 → 1.1.0).
- **PATCH** – багфікси, дрібні зміни без нових функцій (наприклад, 1.1.0 → 1.1.1).

Приклад еволюції:
- `1.0.0` — перший стабільний реліз.
- `1.1.0` — додано нову функцію «статистика по категоріях».
- `1.1.1` — виправлено баг у підрахунку сум.
- `2.0.0` — переписано інтерфейс, несумісно зі старими даними.

## Стратегія Git (Simplified GitFlow)

Ми застосовуємо спрощений **GitFlow** для невеликої команди (1–2 розробники):

- **main** — стабільні релізні версії.
- **develop** — інтеграційна гілка для розробки.
- **feature/*** — нові функції (наприклад, `feature/add-expense-form`).
- **release/*** — підготовка до релізу.
- **hotfix/*** — термінові виправлення у main.
